## Vị trí yêu cầu chung và nội dung giữ lại

- [Khái niệm và vai trò](https://client-ifz4.vercel.app/#/read/visual-studio#identity): Visual Studio là IDE: nơi soạn code, quản lý project, build, debug và dùng công cụ phân tích. .NET CLI là giao diện dòng lệnh của SDK; NuGet là hệ thống package của .NET. IDE không phải runtime và không phải ngôn ngữ; ứng dụng không cần mở Visual Studio để chạy sau khi được triển khai đúng..
- [Nó giải quyết vấn đề gì?](https://client-ifz4.vercel.app/#/read/visual-studio#problem): Nếu dùng một editor thuần, lập trình viên phải tự phối hợp lệnh build, tìm file lỗi, xem giá trị biến và quản lý package. IDE gom các thao tác vào cùng môi trường. CLI giữ cách build lặp lại trong terminal/CI mà không phụ thuộc thao tác chuột của từng người..
- [Tại sao nên dùng nó?](https://client-ifz4.vercel.app/#/read/visual-studio#benefits): Solution Explorer, IntelliSense, breakpoint, Watch và Call Stack giúp học theo dấu chương trình. NuGet quản lý thư viện và dependency thay việc copy DLL thủ công. Visual Studio Community thuận tiện trên Windows; CLI và VS Code là lựa chọn hợp lệ cho nhiều nền tảng, không phải chỉ có một công cụ mới học được .NET..
- [Giới hạn và điều kiện áp dụng](https://client-ifz4.vercel.app/#/read/visual-studio#limits): Không cài mọi workload nếu chỉ viết console; chọn thành phần cần thiết để giảm tải máy. Không gửi thư mục bin/obj hay thông tin đăng nhập NuGet vào Git. Không dựa vào thao tác IDE không được ghi lại nếu người khác/CI cần build cùng project..
- [Cơ chế hoạt động cốt lõi](https://client-ifz4.vercel.app/#/read/visual-studio#mechanism): Project .csproj mô tả SDK, TargetFramework, properties và PackageReference. Solution nhóm nhiều project cho việc quản lý, không bắt buộc với một project độc lập. dotnet restore giải dependency; build chạy MSBuild/compiler; debug gắn debugger vào process và dùng symbol để ánh xạ lệnh máy về dòng source..
- [Các khái niệm cốt lõi](https://client-ifz4.vercel.app/#/read/visual-studio#concepts): Project / solution, SDK / workload, NuGet package.
- [Tương tác với thành phần khác](https://client-ifz4.vercel.app/#/read/visual-studio#integration): Git theo dõi source và cấu hình cần chia sẻ; NuGet lấy package từ nguồn cấu hình trong NuGet.Config. Secret feed nằm trong cơ chế credential riêng, không commit. launchSettings.json cấu hình chạy local, không phải toàn bộ cấu hình production..
- [Ví dụ mở đầu và cách chạy](https://client-ifz4.vercel.app/#/read/visual-studio#hello): tài liệu cụ thể ở cuối bài.
- [Cấu trúc thư mục & cấu hình](https://client-ifz4.vercel.app/#/read/visual-studio#structure): Bố cục chính xác của từng ví dụ được liệt kê trong khối file của ví dụ đó. Đặt mỗi mẫu trong thư mục trống riêng; xem Hướng dẫn chạy chung để tạo Console, hiểu bin/obj và debug. Project nhiều file hoặc lab có nút tải đầy đủ và lệnh chạy riêng..
- [Debug & log lỗi](https://client-ifz4.vercel.app/#/read/visual-studio#debug): F9 bật breakpoint, F5 chạy debug, F10 bước qua, F11 bước vào. Dùng Locals/Watch xem giá trị và Call Stack xem đường gọi. Nếu breakpoint không được hit, kiểm tra đúng process/project khởi động, build Debug và symbol/source đang khớp..
- [Tài liệu & cộng đồng](https://client-ifz4.vercel.app/#/read/visual-studio#resources): tài liệu cụ thể ở cuối bài.

## [Nền tảng junior cần giải thích được](https://client-ifz4.vercel.app/#/read/visual-studio#junior)

restore giải dependency; build kiểm tra và biên dịch; run có thể build rồi chạy; test chạy test project với runner tương ứng; publish chuẩn bị output để triển khai. Debug/Release là cấu hình build, không phải tên môi trường Development/Production. Symbol PDB giúp ánh xạ lệnh đang chạy tới source.

NuGet có dependency trực tiếp trong PackageReference và dependency bắc cầu từ các gói đó. NuGet.Config khai báo nguồn; ProjectReference trỏ project. global.json chọn SDK và roll-forward theo chính sách của nó; không thay target framework. Không ghi credential feed vào source control.

## [Đào sâu middle và các đánh đổi](https://client-ifz4.vercel.app/#/read/visual-studio#middle)

Build tái lập cần khóa/version dependency phù hợp, SDK thống nhất, nguồn package sẵn có và cấu hình CI. Trong .NET 10 có lệnh dạng noun-first dotnet package list; dùng --include-transitive --vulnerable để xem thông tin rủi ro theo dữ liệu nguồn, không coi không có cảnh báo là chứng nhận an toàn. Breakpoint rỗng có thể do sai process, tối ưu Release hoặc symbol/source không khớp.
