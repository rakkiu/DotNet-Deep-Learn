## Vị trí yêu cầu chung và nội dung giữ lại

- [Bản chất và vai trò](https://client-ifz4.vercel.app/#/read/csharp-static#identity): static gắn member với type thay vì từng instance. Static method có thể gọi qua tên type; static field là trạng thái dùng chung cho type được nạp tương ứng. Extension method cổ điển là static method có tham số this, được gọi với cú pháp giống method trên object..
- [Nó giải quyết vấn đề gì?](https://client-ifz4.vercel.app/#/read/csharp-static#problem): Một phép tính không phụ thuộc trạng thái đối tượng không cần tạo object chỉ để gọi. Ngược lại, nếu dùng dữ liệu chung, cần biết rõ ai cùng nhìn thấy nó. static cho phép biểu đạt cả hai nhu cầu nhưng cũng tạo ra rủi ro shared mutable state..
- [Tại sao nên dùng nó?](https://client-ifz4.vercel.app/#/read/csharp-static#benefits): Hàm thuần static như Math.Abs có cách dùng đơn giản và không mang state instance thừa. Extension method thêm thao tác tiện dụng mà không sửa type gốc, là nền tảng của nhiều toán tử LINQ. Lợi ích chủ yếu là mô hình API, không thể mặc định mỗi lần thêm static đều tăng tốc đáng kể..
- [Giới hạn và điều kiện áp dụng](https://client-ifz4.vercel.app/#/read/csharp-static#limits): Không giữ thông tin user hiện tại hoặc DbContext trong static field của web app. Không dùng static như lối tắt vượt DI cho mọi dependency. Không sửa shared state từ nhiều thread nếu chưa có đồng bộ; một biến chung không tự an toàn vì chỉ có một bản..
- [Cơ chế hoạt động cốt lõi](https://client-ifz4.vercel.app/#/read/csharp-static#mechanism): Runtime quản lý dữ liệu static theo type; generic type đóng khác nhau có static state riêng. Static constructor được runtime phối hợp khởi tạo, nhưng mutable state sau đó vẫn cần bảo vệ. Extension method được compiler phân giải theo ngữ cảnh và chuyển thành lời gọi static, không thực sự thêm member vào class gốc..
- [Các khái niệm cốt lõi](https://client-ifz4.vercel.app/#/read/csharp-static#concepts): Instance member, Static member, Extension method.
- [Tương tác với thành phần khác](https://client-ifz4.vercel.app/#/read/csharp-static#integration): LINQ extension được đưa vào scope bằng namespace. Singleton trong DI là một instance được container sở hữu, khác static class; nó vẫn có thể implement interface và được thay khi test. Với nhiều process/server, static state không chia sẻ giữa các máy..
- [Ví dụ mở đầu và cách chạy](https://client-ifz4.vercel.app/#/read/csharp-static#hello): tài liệu cụ thể ở cuối bài.
- [Cấu trúc thư mục & cấu hình](https://client-ifz4.vercel.app/#/read/csharp-static#structure): Bố cục chính xác của từng ví dụ được liệt kê trong khối file của ví dụ đó. - [Debug & log lỗi](https://client-ifz4.vercel.app/#/read/csharp-static#debug): Tìm mọi nơi ghi static field và vòng đời process. Test bị phụ thuộc thứ tự thường do state tĩnh còn sót. Với generic, kiểm tra type argument; với extension không gọi được, kiểm tra using, kiểu receiver và khả năng có instance method trùng tên..

## [Nền tảng junior cần giải thích được](https://client-ifz4.vercel.app/#/read/csharp-static#junior)

Instance member thuộc từng object; static member thuộc type được nạp. const là hằng compile-time, readonly gán trong các vị trí cho phép của instance; static readonly là field type không gán lại ngoài khởi tạo hợp lệ. Một readonly reference tới List vẫn cho sửa List.

Extension this truyền thống nằm trong static class có namespace trong scope. sum.Twice() tương ứng NumberExtensions.Twice(sum), không thêm virtual member vào type gốc. Instance member phù hợp được ưu tiên; extension được phân giải theo kiểu tĩnh, không override class.

## [Đào sâu middle và các đánh đổi](https://client-ifz4.vercel.app/#/read/csharp-static#middle)

Static constructor có bảo đảm chạy tối đa một lần theo type load thích hợp, nhưng không tóm tắt mọi trường hợp thành lần đầu chạm tên type: beforefieldinit và cách khai báo ảnh hưởng thời điểm khởi tạo. Lỗi khởi tạo có thể xuất hiện như TypeInitializationException. Lazy<T> kiểm soát khởi tạo lười theo mode, không làm mọi thao tác sau đó thread-safe. Static generic Cache<int> và Cache<string> có state riêng; nhiều process không chia sẻ static.
