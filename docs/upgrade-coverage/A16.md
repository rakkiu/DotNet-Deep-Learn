## Vị trí yêu cầu chung và nội dung giữ lại

- [Bản chất và vai trò](https://client-ifz4.vercel.app/#/read/oop-interfaces#identity): Interface định nghĩa các khả năng mà một type cam kết cung cấp. Caller dùng hợp đồng như IMessageSender thay vì gắn chặt với EmailSender. Interface không chứa trạng thái instance theo cách class làm; C# hiện đại có thêm default implementation và static abstract member với quy tắc riêng..
- [Nó giải quyết vấn đề gì?](https://client-ifz4.vercel.app/#/read/oop-interfaces#problem): Nếu một service tự new lớp gửi email cụ thể, test phải chạm dịch vụ thật và thay nhà cung cấp sẽ kéo theo sửa caller. Interface tạo ranh giới giữa điều cần và cách làm, giúp mô tả dependency nhỏ đúng nhu cầu..
- [Tại sao nên dùng nó?](https://client-ifz4.vercel.app/#/read/oop-interfaces#benefits): Một class có thể implement nhiều interface; mỗi caller chỉ cần nhìn phần khả năng liên quan. So với abstract class, interface phù hợp hợp đồng giữa các type không chung cây kế thừa hay state. Không phải mọi class đều cần một interface giống hệt để trông có kiến trúc..
- [Giới hạn và điều kiện áp dụng](https://client-ifz4.vercel.app/#/read/oop-interfaces#limits): Không tạo interface có hàng chục phương thức không liên quan, buộc implementation ném NotSupportedException. Không coi việc có chữ I là đã đạt loose coupling nếu caller vẫn ép kiểu về class cụ thể. Nếu không có ranh giới hay nhu cầu thay thế rõ, dùng class trực tiếp có thể tốt hơn..
- [Cơ chế hoạt động cốt lõi](https://client-ifz4.vercel.app/#/read/oop-interfaces#mechanism): Compiler kiểm tra implementation cung cấp các member cần thiết. Biến interface có thể giữ tham chiếu đến implementation tương thích; lời gọi được dispatch đến member thích hợp của object. Explicit interface implementation cho phép cung cấp hành vi chỉ qua view interface. Contract phải bao gồm cả ngữ nghĩa, không chỉ chữ ký..
- [Các khái niệm cốt lõi](https://client-ifz4.vercel.app/#/read/oop-interfaces#concepts): Interface, Implementation, Thay thế dependency.
- [Tương tác với thành phần khác](https://client-ifz4.vercel.app/#/read/oop-interfaces#integration): DI ánh xạ interface tới implementation; fake/mock dùng cùng contract trong test. IDisposable và IEnumerable là interface nền của using và foreach. Một interface repository không tự bảo đảm truy vấn nhanh, bảo mật hay tính nhất quán database..
- [Ví dụ mở đầu và cách chạy](https://client-ifz4.vercel.app/#/read/oop-interfaces#hello): tài liệu cụ thể ở cuối bài.

Với lỗi thiếu member, đối chiếu cả kiểu trả về, generic parameter và accessibility. Nếu object có member nhưng không gọi qua class được, xem có explicit interface implementation không..

## [Nền tảng junior cần giải thích được](https://client-ifz4.vercel.app/#/read/oop-interfaces#junior)

Interface mô tả khả năng; abstract class có thể mang instance state, constructor và code dùng chung. Class chỉ có một base class trực tiếp nhưng có thể implement nhiều interface. Explicit implementation chỉ gọi qua view interface tương ứng, không nhất thiết thành public member thấy trực tiếp trên class.

Contract gồm nullability, lỗi, side effects và điều kiện sử dụng chứ không chỉ tên method. Struct cũng implement interface được; conversion struct sang interface có thể boxing, còn generic constraint có thể tránh boxing ở một số đường gọi.

Bảng **Chọn abstraction**: Thuộc tính / Interface / Abstract class. State instance/constructor — Không theo mô hình field/constructor class — Có; Số contract class có thể nhận — Nhiều interface — Một base class trực tiếp; Mục đích — Khả năng/hợp đồng — Khung và state chung có quan hệ is-a.

## [Đào sâu middle và các đánh đổi](https://client-ifz4.vercel.app/#/read/oop-interfaces#middle)

Default interface implementation từ C# 8 cung cấp hành vi mặc định, không cho interface tùy ý có field state như class. Static abstract members từ C# 11 đặt hợp đồng static dùng qua generic constraint, không được gọi qua mọi instance như method thường. Chỉ dùng nếu đúng bài toán; không kết luận interface luôn tốt hơn abstract class.
