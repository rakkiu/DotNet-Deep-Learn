## Vị trí yêu cầu chung và nội dung giữ lại

- [Bản chất và vai trò](https://client-ifz4.vercel.app/#/read/dotnet-threads#identity): Thread đại diện một luồng thực thi trong process. Mỗi thread có call stack riêng; nhiều thread có thể truy cập cùng object trên heap. Thread khác với Task: Task là abstraction về công việc/kết quả và không luôn gắn với một thread riêng..
- [Nó giải quyết vấn đề gì?](https://client-ifz4.vercel.app/#/read/dotnet-threads#problem): Một luồng duy nhất phải làm tính toán dài có thể giữ UI hoặc việc khác đứng yên. Tạo thread riêng cho phép một đường thực thi độc lập, nhưng buộc lập trình viên quản lý khi bắt đầu, khi kết thúc, trao đổi dữ liệu và xử lý lỗi..
- [Tại sao nên dùng nó?](https://client-ifz4.vercel.app/#/read/dotnet-threads#benefits): Thread thủ công hữu ích cho vòng lặp chuyên biệt cần kiểm soát luồng rõ ràng hoặc API blocking đặc thù. Với phần lớn công việc thông thường, ThreadPool/TPL quản lý tài nguyên dễ hơn. Không nên đánh giá Thread như bản cũ luôn phải bỏ, mà theo mức kiểm soát cần thiết..
- [Giới hạn và điều kiện áp dụng](https://client-ifz4.vercel.app/#/read/dotnet-threads#limits): Không tạo một thread mới cho mỗi HTTP request hoặc mỗi phần tử danh sách. Không dùng Thread.Abort để dừng cưỡng bức trên .NET hiện đại. Không bỏ thread chạy vô hạn mà không có chính sách hủy/dọn tài nguyên..
- [Cơ chế hoạt động cốt lõi](https://client-ifz4.vercel.app/#/read/dotnet-threads#mechanism): new Thread tạo object mô tả; Start lên lịch đường thực thi và một Thread instance không được start lại sau khi hoàn tất. Join chặn caller tới khi luồng kết thúc. Foreground thread có thể giữ process sống; background thread không giữ process khi mọi foreground đã kết thúc, và không bảo đảm finally hoàn tất khi process bị đóng..
- [Các khái niệm cốt lõi](https://client-ifz4.vercel.app/#/read/dotnet-threads#concepts): Thread, Join, Foreground / background.
- [Tương tác với thành phần khác](https://client-ifz4.vercel.app/#/read/dotnet-threads#integration): Thread truy cập UI control phải theo quy tắc dispatcher của framework UI. Shared object cần đồng bộ hoặc message passing. CancellationToken hỗ trợ thông báo hủy hợp tác; không tự ngắt mọi API blocking nếu API đó không quan sát token..
- [Ví dụ mở đầu và cách chạy](https://client-ifz4.vercel.app/#/read/dotnet-threads#hello): tài liệu cụ thể ở cuối bài.
- [Cấu trúc thư mục & cấu hình](https://client-ifz4.vercel.app/#/read/dotnet-threads#structure): Bố cục chính xác của từng ví dụ được liệt kê trong khối file của ví dụ đó. Đặt mỗi mẫu trong thư mục trống riêng; xem Hướng dẫn chạy chung để tạo Console, hiểu bin/obj và debug. Project nhiều file hoặc lab có nút tải đầy đủ và lệnh chạy riêng..
- [Debug & log lỗi](https://client-ifz4.vercel.app/#/read/dotnet-threads#debug): Đặt tên thread, mở Threads/Parallel Stacks và Pause All để xem từng đường đang chờ gì. Với app không thoát, tìm foreground thread còn sống. Với state sai ngẫu nhiên, ghi thread ID và xem truy cập shared state có được bảo vệ nhất quán không..
- [Tài liệu & cộng đồng](https://client-ifz4.vercel.app/#/read/dotnet-threads#resources): tài liệu cụ thể ở cuối bài.

## [Nền tảng junior cần giải thích được](https://client-ifz4.vercel.app/#/read/dotnet-threads#junior)

Thread trước Start chưa chạy; Start chỉ một lần, Join chặn caller tới kết thúc hoặc timeout. Sleep chặn thread một khoảng; Task.Delay tạo tác vụ chờ có thể await, khác Join chờ thread. Đọc value sau Join thành công có quan hệ hoàn tất rõ; đọc ngay sau Start chưa có cùng bảo đảm kết quả.

Exception trên thread riêng không tự nhảy vào catch của thread tạo nó. Đặt try/catch ở entry point và kênh chuyển lỗi/kết quả, rồi join trước khi sử dụng. Không dùng bool thường làm cờ hủy chéo thread; CancellationToken cung cấp thông báo hợp tác và khả năng visibility theo API.

## [Đào sâu middle và các đánh đổi](https://client-ifz4.vercel.app/#/read/dotnet-threads#middle)

Foreground có thể giữ process sống, background không bảo đảm dọn khi process đóng; cả hai không thay chính sách shutdown. Token không tự cắt mọi blocking API; chọn API hỗ trợ token hoặc cơ chế đánh thức/timeout phù hợp. Dedicated thread hữu ích khi cần affinity/blocking đặc thù; ThreadPool cho nhiều tác vụ ngắn. UI control cần dispatcher theo framework.
