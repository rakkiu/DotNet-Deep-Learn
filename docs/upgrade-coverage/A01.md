- [Khái niệm và vai trò](https://client-ifz4.vercel.app/#/read/dotnet-first-program#identity): .NET là một nền tảng phát triển phần mềm gồm runtime, thư viện nền, trình biên dịch và bộ công cụ SDK. C# là ngôn ngữ dùng để diễn đạt chương trình; .NET là hệ sinh thái giúp xây dựng và thực thi chương trình đó. ASP.NET Core là framework web xây trên .NET, còn Visual Studio là công cụ làm việc với mã nguồn..

Điều này giúp cùng một nhóm dùng C# cho console, API và tác vụ nền; không có nghĩa mọi ứng dụng GUI hay thư viện Windows đều tự chạy đa nền tảng..

Garbage Collector đi từ GC roots để xác định object còn reachable và thu vùng không còn reachable; tài nguyên như file/socket vẫn cần Dispose. Native AOT là lối triển khai khác, biên dịch trước ra mã máy và có các giới hạn riêng về reflection/code động..

## [Nền tảng junior cần giải thích được](https://client-ifz4.vercel.app/#/read/dotnet-first-program#junior)

Managed code là mã chạy dưới các dịch vụ runtime. CLR quản lý thực thi; BCL là thư viện nền như Console, collections, I/O. Assembly chứa IL và metadata; process là tiến trình hệ điều hành nạp chương trình, không phải tên khác của assembly. Một project có thể chạy không cần solution.

dotnet build tạo output thường ở bin/Debug/net10.0; run build khi cần rồi chạy. publish gom output triển khai, thường trong bin/Release/net10.0/publish. TargetFramework net10.0 chọn API/runtime mục tiêu; Nullable enable bật phân tích null. global.json chọn SDK phát triển, không cài runtime cho máy nhận.

Sơ đồ **Từ source tới process**: Source .cs → Roslyn kiểm tra kiểu → Assembly: IL + metadata → CLR nạp assembly → JIT hoặc đường Native AOT → Process gọi BCL, OS; GC quản lý reachability.

## [Đào sâu middle và các đánh đổi](https://client-ifz4.vercel.app/#/read/dotnet-first-program#middle)

GC xác định object reachable (còn truy cập được) từ GC roots như tham chiếu trong stack đang hoạt động, static và handle thích hợp. GC không đếm số reference; một chu kỳ object không còn reachable vẫn thu hồi được. Dispose kết thúc quyền sử dụng tài nguyên, không ra lệnh GC thu object ngay.

Framework-dependent cần runtime thích hợp trên máy nhận; self-contained mang runtime theo RID và cần được publish lại khi runtime có bản vá. JIT cho phép tối ưu lúc chạy nhưng có chi phí khởi động; Native AOT có thể giảm startup và yêu cầu phân tích trimming/code động, không phải cứ AOT là nhỏ hoặc nhanh hơn mọi workload. Nền tảng thực tế còn tùy workload và thư viện.
