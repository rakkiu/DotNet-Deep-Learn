## Vị trí yêu cầu chung và nội dung giữ lại

- [Bản chất và vai trò](https://client-ifz4.vercel.app/#/read/async-await#identity): async/await là cú pháp viết luồng chờ tác vụ theo dạng tuần tự, thường với Task/Task<T>. Bất đồng bộ cho phép không block thread trong khi một API I/O phù hợp đang chờ. async không có nghĩa tự tạo thread, chạy song song hoặc tự làm phép tính nhanh hơn..
- [Nó giải quyết vấn đề gì?](https://client-ifz4.vercel.app/#/read/async-await#problem): Code đồng bộ gọi mạng có thể giữ UI không phản hồi hoặc chiếm worker thread server chỉ để chờ. Callback lồng nhau làm xử lý lỗi và thứ tự công việc khó đọc. async/await giữ cấu trúc try/catch và luồng logic rõ trong khi runtime quản lý continuation..
- [Tại sao nên dùng nó?](https://client-ifz4.vercel.app/#/read/async-await#benefits): Giao diện phản hồi và khả năng phục vụ nhiều tác vụ I/O có thể tốt hơn khi không block. So với callback thủ công, code gần với cách diễn đạt quy trình. Nếu công việc đã có kết quả sẵn hoặc rất nhỏ, async có overhead và không phải mọi method đều cần thêm async..
- [Giới hạn và điều kiện áp dụng](https://client-ifz4.vercel.app/#/read/async-await#limits): Không dùng async void ngoài ngữ cảnh event handler phù hợp. Không gọi .Result hoặc Wait để lấy kết quả ở giữa chuỗi async. Không dùng Task.Run cho phép gọi mạng vốn đã hỗ trợ async, và không bỏ task chạy mà không ai quan sát lỗi..
- [Cơ chế hoạt động cốt lõi](https://client-ifz4.vercel.app/#/read/async-await#mechanism): Compiler biến async method thành state machine. Hàm bắt đầu đồng bộ; nếu awaitable chưa hoàn thành, lưu trạng thái, đăng ký continuation và trả quyền cho caller. Nếu nó đã hoàn thành, code có thể đi tiếp ngay mà không suspend. Sau await, context/awaiter quyết định cách tiếp tục; ConfigureAwait(false) không hứa tạo thread mới..
- [Các khái niệm cốt lõi](https://client-ifz4.vercel.app/#/read/async-await#concepts): Async method, Continuation, Completed awaitable.
- [Tương tác với thành phần khác](https://client-ifz4.vercel.app/#/read/async-await#integration): ASP.NET Core controller await service, service await EF/HttpClient. Truyền CancellationToken xuyên chuỗi, DisposeAsync khi tài nguyên cần dọn bất đồng bộ. UI có synchronization context để cập nhật control; code thư viện phải cân nhắc context thay vì sao chép ConfigureAwait một cách máy móc..
- [Ví dụ mở đầu và cách chạy](https://client-ifz4.vercel.app/#/read/async-await#hello): tài liệu cụ thể ở cuối bài.
- [Cấu trúc thư mục & cấu hình](https://client-ifz4.vercel.app/#/read/async-await#structure): Bố cục chính xác của từng ví dụ được liệt kê trong khối file của ví dụ đó. Đặt mỗi mẫu trong thư mục trống riêng; xem Hướng dẫn chạy chung để tạo Console, hiểu bin/obj và debug. Project nhiều file hoặc lab có nút tải đầy đủ và lệnh chạy riêng..
- [Debug & log lỗi](https://client-ifz4.vercel.app/#/read/async-await#debug): Theo dõi Tasks và async call stack; xem task có completed/faulted/canceled hay không. Đặt breakpoint trước/sau await để biết đoạn nào chạy đồng bộ. Với treo, tìm blocking .Result/Wait và tài nguyên chưa hoàn tất, không giả định await nào cũng làm đổi thread..

## [Nền tảng junior cần giải thích được](https://client-ifz4.vercel.app/#/read/async-await#junior)

Compiler sinh state machine lưu state/continuation. Task/Task<T> biểu diễn hoàn tất/kết quả; async void khó được caller quan sát, chủ yếu dành event handler phù hợp. Awaitable đã hoàn tất có thể đi tiếp đồng bộ; chưa hoàn tất có thể suspend và trả về caller.

Method nhận CancellationToken và truyền tới I/O; CancelAfter/linked token phối hợp timeout/caller shutdown. Cancel là yêu cầu hợp tác. return task chuyển Task cho caller; return await trong try/catch hoặc using có thể cần để boundary còn sống tới lúc thao tác thật kết thúc, không thay nhau vô điều kiện.

## [Đào sâu middle và các đánh đổi](https://client-ifz4.vercel.app/#/read/async-await#middle)

UI SynchronizationContext khác ASP.NET Core mặc định; .Result có thể deadlock ở context cần trở lại và blocking nhiều vẫn có thể làm server starvation. ConfigureAwait(false) không ép đổi thread và không tự xóa ExecutionContext/AsyncLocal. TCS làm bridge nên cân nhắc RunContinuationsAsynchronously để tránh inline continuation ngoài dự kiến. ValueTask có hợp đồng sử dụng/await riêng, chỉ tối ưu sau đo, không thay mọi Task.
