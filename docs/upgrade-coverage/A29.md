## Vị trí yêu cầu chung và nội dung giữ lại

- [Bản chất và vai trò](https://client-ifz4.vercel.app/#/read/relational-databases#identity): SQL là ngôn ngữ mô tả truy vấn và thay đổi dữ liệu quan hệ. SQL Server là hệ quản trị database chạy dạng dịch vụ; SQLite là engine nhúng thường lưu một database trong file. EF Core là ORM nằm trên các engine này, không phải thứ thay thế database. SQLite được dùng cho ví dụ độc lập, còn bài giảng giới thiệu provider SQL Server..
- [Nó giải quyết vấn đề gì?](https://client-ifz4.vercel.app/#/read/relational-databases#problem): Lưu nhiều file text tự do khiến truy vấn, liên kết và cập nhật đồng thời khó nhất quán. Database cung cấp bảng, khóa, constraint, transaction và engine query. SQL biểu đạt tập dữ liệu cần lấy mà không tự viết vòng lặp đọc từng file, nhưng vẫn phải thiết kế schema và index..
- [Tại sao nên dùng nó?](https://client-ifz4.vercel.app/#/read/relational-databases#benefits): SQL Server phù hợp mô hình nhiều client kết nối một dịch vụ với quyền/operation tập trung; SQLite nhẹ, nhúng, dễ tạo ví dụ local. So với file JSON, database quan hệ hỗ trợ truy vấn và ràng buộc tốt hơn cho dữ liệu có cấu trúc. Không có engine nào nhanh nhất cho mọi tải và mọi môi trường..
- [Giới hạn và điều kiện áp dụng](https://client-ifz4.vercel.app/#/read/relational-databases#limits): Không chọn SQLite cho tải nhiều writer từ nhiều máy như thể nó là server database đầy đủ. Không vận hành SQL Server chỉ để lưu một tệp cấu hình nhỏ. Không nối input vào SQL string và không cho tài khoản app quyền quản trị schema nếu chỉ cần CRUD..
- [Cơ chế hoạt động cốt lõi](https://client-ifz4.vercel.app/#/read/relational-databases#mechanism): SQL engine parse và tối ưu query thành execution plan; index cung cấp đường tìm dữ liệu thay việc quét toàn bộ trong những trường hợp phù hợp. Primary key định danh dòng, foreign key ràng buộc tham chiếu. Transaction tạo phạm vi thay đổi có tính nhất quán theo isolation/engine, không đồng nghĩa mọi thao tác tự không bao giờ xung đột..
- [Các khái niệm cốt lõi](https://client-ifz4.vercel.app/#/read/relational-databases#concepts): Schema / table, Index / query plan, Transaction.
- [Tương tác với thành phần khác](https://client-ifz4.vercel.app/#/read/relational-databases#integration): ADO.NET provider gửi command có parameter; EF Core dịch LINQ rồi gọi provider. Connection string chọn engine/server/database và xác thực; backend giữ thông tin này. Migration đổi schema, backup bảo vệ dữ liệu, còn cache là bản sao tăng tốc có chính sách riêng..
- [Ví dụ mở đầu và cách chạy](https://client-ifz4.vercel.app/#/read/relational-databases#hello): tài liệu cụ thể ở cuối bài.

## [Nền tảng junior cần giải thích được](https://client-ifz4.vercel.app/#/read/relational-databases#junior)

PK định danh, FK ràng buộc tham chiếu; unique chống trùng, NOT NULL cấm thiếu và CHECK áp quy tắc hàng theo engine. UPDATE/DELETE phải có điều kiện đúng. IS NULL kiểm tra null, so =NULL không có semantics như so số. INNER JOIN chỉ giữ match, LEFT JOIN còn giữ dòng trái không match. GROUP BY/HAVING nhóm và lọc nhóm; không có ORDER BY thì không hứa thứ tự.

DataLab là lối chạy SQL qua Microsoft.Data.Sqlite/EF provider .NET, không bắt cài sqlite3 shell. Database luôn mới trong thư mục temp riêng. FromSql interpolation hoặc DbParameter đưa giá trị riêng khỏi SQL text, khác nối input vào string lệnh.

Bảng **Hai engine trong bối cảnh học**: Thuộc tính / SQLite / SQL Server. Mô hình — Engine nhúng/file — Dịch vụ nhiều client; Kiểu/identity — Affinity và INTEGER PRIMARY KEY — Kiểu/cột identity theo SQL Server; Concurrency/isolation — Quy tắc lock/MVCC riêng, hạn chế writer — Cơ chế lock/version/isolation riêng; Test — Nhanh cho relational local — Cần engine tương ứng khi xác minh SQL Server semantics.

## [Đào sâu middle và các đánh đổi](https://client-ifz4.vercel.app/#/read/relational-databases#middle)

ACID phụ thuộc transaction và engine/isolation; dirty/non-repeatable/phantom reads không thể tóm tắt như nhau cho mọi DB. Deadlock cần xử lý theo chính sách retry có giới hạn và đọc lại điều kiện. Index hỗ trợ một số đường tìm nhưng tốn ghi/bộ nhớ và optimizer có thể không chọn. Composite index phụ thuộc thứ tự cột và query cụ thể; xem execution plan. SQL Server khác SQLite về typing, collation, identity, khóa/concurrency và dialect; test SQLite không chứng minh toàn bộ hành vi SQL Server.
