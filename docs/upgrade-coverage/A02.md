## Vị trí yêu cầu chung và nội dung giữ lại

- [Khái niệm và vai trò](https://client-ifz4.vercel.app/#/read/csharp-language#identity): C# là ngôn ngữ lập trình kiểu tĩnh, đa mục đích, hỗ trợ hướng đối tượng, generic, pattern matching và async/await. C# diễn tả chương trình; compiler chuyển chương trình thành dạng thực thi trên nền tảng phù hợp, thường là .NET. Ngôn ngữ, runtime, framework web và IDE là bốn vai trò khác nhau..
- [Nó giải quyết vấn đề gì?](https://client-ifz4.vercel.app/#/read/csharp-language#problem): Một chương trình cần cách mô tả dữ liệu, điều kiện, vòng lặp và ranh giới hàm mà con người có thể đọc/sửa. C# kết hợp cú pháp quen thuộc với hệ thống kiểu và thư viện của .NET để giảm nhiều thao tác quản lý bộ nhớ cấp thấp. Nó không loại bỏ lỗi nghiệp vụ hoặc nhu cầu hiểu tài nguyên..
- [Tại sao nên dùng nó?](https://client-ifz4.vercel.app/#/read/csharp-language#benefits): Compiler phát hiện nhiều sai kiểu và IDE hỗ trợ refactor; generic và nullable làm hợp đồng dữ liệu rõ hơn. Có thể dùng cùng ngôn ngữ cho console, web và service. Lựa chọn còn tùy đội ngũ và hệ sinh thái, không nên khẳng định C# luôn nhanh hơn C++, Java hay Python ở mọi công việc..
- [Giới hạn và điều kiện áp dụng](https://client-ifz4.vercel.app/#/read/csharp-language#limits): Không chọn C# chỉ vì muốn code chạy trực tiếp trong mọi trình duyệt như JavaScript; mô hình web client có yêu cầu riêng như WebAssembly. Với script ngắn xử lý dữ liệu trong hệ sinh thái đã dùng Python, chuyển ngôn ngữ có thể không mang lại lợi ích. Với hệ nhúng rất hạn chế tài nguyên, phải đánh giá toolchain/runtime..
- [Cơ chế hoạt động cốt lõi](https://client-ifz4.vercel.app/#/read/csharp-language#mechanism): Roslyn phân tích cú pháp, ràng buộc tên và kiểm tra kiểu trước khi sinh IL/metadata trong cách build phổ biến. Top-level statements là cú pháp rút gọn; compiler tạo điểm vào thay cho việc tự viết Program.Main. Namespace tổ chức tên, còn assembly là đơn vị triển khai, hai thứ không đồng nhất..
- [Các khái niệm cốt lõi](https://client-ifz4.vercel.app/#/read/csharp-language#concepts): Compiler, Namespace, Entry point.
- [Tương tác với thành phần khác](https://client-ifz4.vercel.app/#/read/csharp-language#integration): C# gọi thư viện .NET qua namespace và package reference trong .csproj. Một console app có thể dùng HttpClient gọi API và EF Core truy vấn DB; secret cấu hình không nên được hardcode trong file .cs. C# không tự biến mọi input thành dữ liệu an toàn, vẫn phải parse/validate..
- [Ví dụ mở đầu và cách chạy](https://client-ifz4.vercel.app/#/read/csharp-language#hello): tài liệu cụ thể ở cuối bài.
- [Cấu trúc thư mục & cấu hình](https://client-ifz4.vercel.app/#/read/csharp-language#structure): Bố cục chính xác của từng ví dụ được liệt kê trong khối file của ví dụ đó. Đặt mỗi mẫu trong thư mục trống riêng; xem Hướng dẫn chạy chung để tạo Console, hiểu bin/obj và debug. Project nhiều file hoặc lab có nút tải đầy đủ và lệnh chạy riêng..
- [Debug & log lỗi](https://client-ifz4.vercel.app/#/read/csharp-language#debug): Chạy dotnet build để đọc lỗi compiler trước khi chạy. Đặt breakpoint ở Console.WriteLine, xem biến trong Locals và bước qua bằng F10. Phân biệt lỗi compile-time (sai kiểu) với runtime (chia nguyên cho 0) và lỗi logic (tổng tính sai nhưng app vẫn chạy)..
- [Tài liệu & cộng đồng](https://client-ifz4.vercel.app/#/read/csharp-language#resources): tài liệu cụ thể ở cuối bài.

## [Nền tảng junior cần giải thích được](https://client-ifz4.vercel.app/#/read/csharp-language#junior)

Top-level statements và Program.Main là hai cách viết điểm vào có ý nghĩa tương ứng, không hứa sinh IL giống hệt. Trong file dùng top-level, các câu lệnh phải đứng trước khai báo type. Local variable có scope theo khối; namespace tổ chức tên, using directive giúp viết tên ngắn và không cài package.

ImplicitUsings đưa một tập using phổ biến vào compilation theo SDK; tắt nó thì thêm using cần thiết. Access modifiers giới hạn truy cập type/member. ProjectReference nối mã của project khác trong solution/build graph; PackageReference nối gói NuGet có version. C# 14 là ngôn ngữ trong bối cảnh net10.0, không đồng nhất hai số version.

## [Đào sâu middle và các đánh đổi](https://client-ifz4.vercel.app/#/read/csharp-language#middle)

Compiler diagnostics chỉ ra sai cú pháp/kiểu; nullable diagnostics cảnh báo đường null; analyzer kiểm tra các quy tắc thêm. Chúng không chứng minh công thức nghiệp vụ đúng hoặc hạ tầng không lỗi. Lỗi compile-time cần sửa trước run; runtime và logic cần test hoặc debugger.
