## Vị trí yêu cầu chung và nội dung giữ lại

- [Bản chất và vai trò](https://client-ifz4.vercel.app/#/read/mvc-views#identity): MVC tách Model (dữ liệu/quy tắc), View (trình bày) và Controller (điều phối request). Razor là cú pháp template .cshtml kết hợp HTML và C# để tạo HTML phía server. Trình duyệt không thực thi C# trong file Razor theo cách nó chạy JavaScript..
- [Nó giải quyết vấn đề gì?](https://client-ifz4.vercel.app/#/read/mvc-views#problem): Nếu HTML, đọc request và truy vấn database trộn trong một file lớn, sửa giao diện dễ làm hỏng nghiệp vụ. MVC cho một quy ước phân vai và tìm file; ViewModel giúp view nhận đúng dữ liệu cần hiển thị thay vì tự truy vấn nhiều nguồn..
- [Tại sao nên dùng nó?](https://client-ifz4.vercel.app/#/read/mvc-views#benefits): View mạnh kiểu có @model cho phép kiểm tra tên property và refactor tốt hơn ViewBag động. Layout dùng lại khung HTML; partial view tách phần trình bày. So với tạo chuỗi HTML bằng nối chuỗi, Razor hỗ trợ encoding mặc định và cú pháp gần với cấu trúc giao diện..
- [Giới hạn và điều kiện áp dụng](https://client-ifz4.vercel.app/#/read/mvc-views#limits): Không nhét truy vấn database và quy tắc phân quyền vào view. Không dùng Html.Raw với dữ liệu chưa tin cậy. Không chọn MVC nếu client cần ứng dụng tương tác phức tạp mà mọi thay đổi đều phải tải trang; có thể cần JS hoặc một mô hình UI khác phù hợp..
- [Cơ chế hoạt động cốt lõi](https://client-ifz4.vercel.app/#/read/mvc-views#mechanism): Routing tìm action; controller nhận input, gọi service rồi return View(model). View engine tìm Views/TenController/TenAction.cshtml hoặc vị trí theo cấu hình; Razor tạo HTML và thường HTML-encode biểu thức. _ViewStart có thể chọn layout, _ViewImports khai báo namespace/tag helpers dùng chung..
- [Các khái niệm cốt lõi](https://client-ifz4.vercel.app/#/read/mvc-views#concepts): View model, Razor, HTML encoding.
- [Tương tác với thành phần khác](https://client-ifz4.vercel.app/#/read/mvc-views#integration): Controller nhận service qua DI và ánh xạ dữ liệu thành ViewModel; view dùng Tag Helpers tạo link/form. CSS/JS trong wwwroot chạy phía client. Validation client hỗ trợ trải nghiệm, nhưng server vẫn phải kiểm tra dữ liệu và quyền trước khi ghi database..
- [Ví dụ mở đầu và cách chạy](https://client-ifz4.vercel.app/#/read/mvc-views#hello): tài liệu cụ thể ở cuối bài.
- [Cấu trúc thư mục & cấu hình](https://client-ifz4.vercel.app/#/read/mvc-views#structure): Bố cục chính xác của từng ví dụ được liệt kê trong khối file của ví dụ đó. Đặt mỗi mẫu trong thư mục trống riêng; xem Hướng dẫn chạy chung để tạo Console, hiểu bin/obj và debug. Project nhiều file hoặc lab có nút tải đầy đủ và lệnh chạy riêng..
- [Debug & log lỗi](https://client-ifz4.vercel.app/#/read/mvc-views#debug): Nếu view không tìm thấy, đọc danh sách vị trí được tìm trong exception và kiểm tra tên controller/action/file. Nếu property sai, kiểm tra @model và kiểu object truyền vào View. Dùng View Source và DevTools để phân biệt HTML server sinh với thay đổi DOM bằng JS..
- [Tài liệu & cộng đồng](https://client-ifz4.vercel.app/#/read/mvc-views#resources): tài liệu cụ thể ở cuối bài.

## [Nền tảng junior cần giải thích được](https://client-ifz4.vercel.app/#/read/mvc-views#junior)

WebLab dùng StudentListViewModel.Names, @model khai báo type và @Model truy cập instance; foreach tạo danh sách, empty state xử lý không có dữ liệu. _ViewImports đăng ký Tag Helpers; _ViewStart chọn layout; _Layout chứa RenderBody; partial _Name trình bày một tên. ViewData/ViewBag gắn dữ liệu cho cùng lần render; TempData giữ dữ liệu qua request tiếp theo theo provider/cấu hình và cách đọc.

View(model) với ViewModel mạnh kiểu không cần cast object thường lệ. Mẫu string cũ dùng (object) để tránh overload View(string viewName). Tag Helpers tạo link/form đúng action; form POST với validation sai trả view cùng input và lỗi, thành công redirect để refresh không tự gửi lại POST.

## [Đào sâu middle và các đánh đổi](https://client-ifz4.vercel.app/#/read/mvc-views#middle)

Razor HTML-encode dữ liệu trong bối cảnh HTML phổ biến, nhưng encoding theo ngữ cảnh không có nghĩa có thể đưa input tùy ý vào JS/URL an toàn. Html.Raw dữ liệu không tin cậy tạo XSS. Form cookie cần antiforgery và server validation; client validation chỉ hỗ trợ UX. Partial tập trung render; View Component phù hợp khi có logic chuẩn bị dữ liệu riêng, không query DbContext ngay trong view.
