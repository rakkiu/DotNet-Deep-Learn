## Vị trí yêu cầu chung và nội dung giữ lại

- [Bản chất và vai trò](https://client-ifz4.vercel.app/#/read/efcore-relationships#identity): Relationship biểu diễn quan hệ giữa entity: một-một, một-nhiều và nhiều-nhiều. Foreign key là giá trị liên kết ở database; navigation property là cách đi từ object này sang object liên quan trong C#. Hai thứ có liên hệ nhưng không phải cùng một trường dữ liệu..
- [Nó giải quyết vấn đề gì?](https://client-ifz4.vercel.app/#/read/efcore-relationships#problem): Nếu chỉ có danh sách object rời nhau, code phải tự ghép sinh viên với khoa và bảo đảm không tham chiếu tới khoa không tồn tại. Database dùng key/constraint bảo vệ tính toàn vẹn; ORM cần mapping để biết cách materialize và lưu các mối liên hệ đó..
- [Tại sao nên dùng nó?](https://client-ifz4.vercel.app/#/read/efcore-relationships#benefits): Mapping rõ giảm SQL join/ghép object thủ công và giúp diễn đạt aggregate theo nhu cầu. Include và projection hỗ trợ tải dữ liệu cần thiết. So với lazy loading vô tội vạ, truy vấn có chủ đích dễ kiểm soát số query và lượng dữ liệu hơn..
- [Giới hạn và điều kiện áp dụng](https://client-ifz4.vercel.app/#/read/efcore-relationships#limits): Không Include toàn bộ graph chỉ để hiển thị vài cột. Không bật lazy loading rồi truy cập navigation trong vòng lặp lớn mà không theo dõi N+1. Không dựa vào cascade delete mặc định khi quan hệ có dữ liệu cần giữ hoặc nhiều đường cascade phức tạp..
- [Cơ chế hoạt động cốt lõi](https://client-ifz4.vercel.app/#/read/efcore-relationships#mechanism): EF xác định principal/dependent, khóa chính/khóa ngoại và navigation qua convention hoặc Fluent API. Eager loading tải liên quan trong query được cấu hình, có thể dùng một hoặc nhiều SQL query tùy split-query. Explicit loading được gọi chủ động; lazy loading chỉ hoạt động khi cấu hình cơ chế tương ứng, không phải mọi navigation tự truy vấn..
- [Các khái niệm cốt lõi](https://client-ifz4.vercel.app/#/read/efcore-relationships#concepts): Khóa ngoại, Navigation, Eager loading.
- [Tương tác với thành phần khác](https://client-ifz4.vercel.app/#/read/efcore-relationships#integration): Database constraint bảo vệ dữ liệu ngay cả ngoài app; EF relationship fixup đồng bộ các navigation/key được track theo cơ chế của context. API nên trả DTO tránh vòng lặp serialize và tránh lộ dữ liệu liên quan không được phép. Many-to-many có join table; có thể cần entity tường minh nếu quan hệ có thêm thuộc tính..

## [Nền tảng junior cần giải thích được](https://client-ifz4.vercel.app/#/read/efcore-relationships#junior)

Principal là phía được tham chiếu; dependent có FK. Required/optional thể hiện bằng FK/nullability và mapping, không chỉ có navigation. Một-một cần ràng buộc duy nhất trên FK thích hợp; nhiều-nhiều có bảng join, có thể dùng explicit Enrollment khi quan hệ mang RegisteredAt.

Fluent API trong DataLab định nghĩa PK join, FK, one-to-one Profile và DeleteBehavior.Restrict cho khoa. Navigation chưa load không chứng minh không có dữ liệu. Eager Include tải theo truy vấn; explicit loading do code gọi; lazy loading cần proxy/ILazyLoader và cấu hình thực, không tự xảy ra với mọi virtual property.

Sơ đồ **Quan hệ trong DataLab**: Department.Id (principal) ← Student.DepartmentId (required, Restrict) → Student.Id ← Profile.StudentId (unique, một-một) → Student ↔ Enrollment(RegisteredAt) ↔ Course (nhiều-nhiều).

## [Đào sâu middle và các đánh đổi](https://client-ifz4.vercel.app/#/read/efcore-relationships#middle)

N+1 làm tăng round-trip; Include nhiều collection có thể cartesian explosion. AsSplitQuery đổi sang nhiều lệnh với trade-off network và nhất quán nếu dữ liệu đổi giữa các query; không luôn tốt hơn. Filtered Include với tracking fixup có thể làm graph chứa phần tử đã track ngoài filter. Projection DTO giúp chỉ lấy dữ liệu UI cần và tránh vòng lặp serializer.

Giải thích: Ví dụ sử dụng SQLite in-memory để không phụ thuộc SQL Server. EnsureCreated chỉ tạo schema cho ví dụ độc lập này; mục Migrations có luồng riêng cho database được quản lý bằng migration. Package 10.0.0 là mốc minh họa tương thích .NET 10, không phải khuyến nghị bỏ qua các bản vá. SaveChanges lưu một khoa và hai sinh viên với khóa ngoại tương ứng. Clear bỏ các object tracked để tránh nhầm relationship fix-up với Include. Truy vấn chọn An vì điểm 8 và tải Department; output là An:CNTT.
