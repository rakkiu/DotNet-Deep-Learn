## Vị trí yêu cầu chung và nội dung giữ lại

Record class vẫn là reference type nhưng compiler hỗ trợ value equality theo member; record struct là value type với cơ chế record. Chọn theo ý nghĩa dữ liệu và identity, không bằng khẩu quyết struct luôn nhanh hơn class..

## [Nền tảng junior cần giải thích được](https://client-ifz4.vercel.app/#/read/csharp-value-modeling#junior)

== có thể được overload, Equals là contract equality, object.Equals xử lý null rồi dispatch phù hợp, ReferenceEquals hỏi identity reference và có thể boxing value types. IEquatable<T> cung cấp contract equality mạnh kiểu. Hai object equal phải có hash bằng nhau; hai hash bằng nhau không chứng minh equal. GetHashCode không là ID bền vững để lưu DB.

init và required có vai trò trong khởi tạo, readonly struct hạn chế mutation của instance; readonly reference không làm object bên trong immutable. with thường shallow copy: record chứa List vẫn có thể chia sẻ cùng List. Entity có identity thường cần suy nghĩ khác DTO/value object như Money.

Bảng **Chọn kiểu**: Kiểu / Copy / Equality mặc định đáng chú ý / Kế thừa. class — Reference — Identity nếu không override — Có class inheritance; struct — Giá trị field — ValueType equality hoặc tùy override — Không kế thừa struct/class khác theo kiểu class; record class — Reference; with tạo bản shallow — Member-based được compiler hỗ trợ — Record inheritance theo quy tắc record; record struct — Giá trị; with copy field — Member-based — Không có class inheritance.

## [Đào sâu middle và các đánh đổi](https://client-ifz4.vercel.app/#/read/csharp-value-modeling#middle)

Mutable struct truyền/copy hoặc gọi member qua readonly receiver có thể tạo defensive copy, nên thay đổi không tới nơi caller tưởng. Struct lớn có chi phí copy; ref/in cũng có trade-off và cần đo. Dictionary key phải giữ equality/hash ổn định khi đang nằm trong collection. Record có member mutable không tự deep immutable; dùng immutable elements/collections hoặc copy có chủ đích khi hợp đồng cần snapshot.
