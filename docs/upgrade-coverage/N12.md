## Vị trí yêu cầu chung và nội dung giữ lại

- [Bản chất và vấn đề cần giải quyết](https://client-ifz4.vercel.app/#/read/dotnet-delivery-basics#identity): Build kiểm tra/biên dịch source; publish chuẩn bị output triển khai, chưa tự có một server production đang chạy. Debug/Release là cấu hình build; Development/Production là môi trường runtime. Docker là lựa chọn đóng gói, không điều kiện bắt buộc học hoặc triển khai mọi app .NET..
- [Chẩn đoán và kiểm chứng](https://client-ifz4.vercel.app/#/read/dotnet-delivery-basics#debug): Chạy output publish từ terminal ngoài IDE với environment/URL rõ. Kiểm tra runtime bằng --list-runtimes, status health và log startup; không dùng launchSettings làm bằng chứng cấu hình production. Smoke test phải trỏ đúng process vừa khởi động..
- [Tài liệu chính thức và đọc tiếp](https://client-ifz4.vercel.app/#/read/dotnet-delivery-basics#resources): tài liệu cụ thể ở cuối bài.

## [Nền tảng junior cần giải thích được](https://client-ifz4.vercel.app/#/read/dotnet-delivery-basics#junior)

Framework-dependent cần runtime phù hợp; self-contained mang runtime theo RID và phải phát hành lại để có runtime đã vá. launchSettings.json chủ yếu phục vụ launch local, không đại diện mọi config production. Dùng environment/config provider và secret store phù hợp, không commit connection credential.

Smoke test thực sự phải khởi động output publish ngoài IDE, gửi request kiểm tra status/body/health. HTTPS có thể kết thúc tại Kestrel hoặc trusted reverse proxy theo kiến trúc, không mặc định tất cả phải IIS. Health live/ready chỉ có ý nghĩa theo policy đo.

## [Đào sâu middle và các đánh đổi](https://client-ifz4.vercel.app/#/read/dotnet-delivery-basics#middle)

CI chạy SDK/dependency versions công bố, build/test và package có thể tái hiện. Schema migration nên là bước kiểm soát script/bundle, compatible rollout thay việc mọi instance tự update. Nhiều process có static/memory cache/locks riêng; Data Protection key/cookie cần cấu hình chia sẻ/lifetime đúng nếu có nhiều node. Timeout/cancel/graceful shutdown/logging cần được thiết kế, không đòi Kubernetes hoặc microservices để đạt mục tiêu này.
