## Vị trí yêu cầu chung và nội dung giữ lại

- [Bản chất và vai trò](https://client-ifz4.vercel.app/#/read/mvc-routing#identity): Routing ánh xạ request tới endpoint dựa trên đường dẫn, HTTP method và các ràng buộc liên quan. Trong MVC, endpoint thường là action của controller. Route parameter là một phần URL; nó khác query string và khác dữ liệu form gửi trong body..
- [Nó giải quyết vấn đề gì?](https://client-ifz4.vercel.app/#/read/mvc-routing#problem): Nếu tự đọc URL rồi viết chuỗi if để chọn hàm, code khó tổ chức và tạo link dễ sai khi đổi đường dẫn. Routing gom quy tắc chọn endpoint, đồng thời hỗ trợ tạo URL từ tên route/action thay vì rải chuỗi đường dẫn khắp view..
- [Tại sao nên dùng nó?](https://client-ifz4.vercel.app/#/read/mvc-routing#benefits): Attribute routing đặt hợp đồng API gần action; conventional routing phù hợp các trang MVC theo quy ước. Route constraint làm đường dẫn rõ hơn; link generation giảm hardcode. Lợi ích nằm ở tính nhất quán và kiểm soát hợp đồng, không phải tự bảo đảm URL có dữ liệu hợp lệ..
- [Giới hạn và điều kiện áp dụng](https://client-ifz4.vercel.app/#/read/mvc-routing#limits): Không dùng route constraint để thay validation nghiệp vụ. Không cho GET gây tác dụng phụ như xóa bản ghi. Không dùng hai route mơ hồ có cùng độ ưu tiên mà chỉ khác tên tham số; tên biến không đủ để routing chọn..
- [Cơ chế hoạt động cốt lõi](https://client-ifz4.vercel.app/#/read/mvc-routing#mechanism): Endpoint routing so khớp mẫu route và policy/method để lấy tập ứng viên, sau đó chọn endpoint. {id:int} chấp nhận segment theo constraint int; {id?} cho phép bỏ qua. Model binding sau đó chuyển route value thành argument. Không khớp đường dẫn có thể thành 404; có path nhưng sai method có thể thành 405..
- [Các khái niệm cốt lõi](https://client-ifz4.vercel.app/#/read/mvc-routing#concepts): Attribute route, Route constraint, HTTP method.
- [Tương tác với thành phần khác](https://client-ifz4.vercel.app/#/read/mvc-routing#integration): Routing phải phối hợp authentication/authorization và middleware theo thứ tự đúng. View dùng asp-controller/asp-action/asp-route-id để tạo URL. Reverse proxy và PathBase có thể ảnh hưởng đường dẫn công khai, nên không tự ghép host từ dữ liệu không tin cậy..
- [Ví dụ mở đầu và cách chạy](https://client-ifz4.vercel.app/#/read/mvc-routing#hello): tài liệu cụ thể ở cuối bài.
- [Cấu trúc thư mục & cấu hình](https://client-ifz4.vercel.app/#/read/mvc-routing#structure): Bố cục chính xác của từng ví dụ được liệt kê trong khối file của ví dụ đó. ## [Nền tảng junior cần giải thích được](https://client-ifz4.vercel.app/#/read/mvc-routing#junior)

Conventional routing dùng mẫu như {controller=Home}/{action=Index}/{id?}; attribute routing gắn đường dẫn/method cạnh action. Defaults điền thiếu, optional cho phép vắng, constraint giúp chọn endpoint. Query string không là segment route. API nên đặt URL theo resource thay tên nội bộ của action.

Literal/parameter/constraint và endpoint policies cùng ảnh hưởng chọn route; thứ tự khai báo không phải quy tắc duy nhất. Url.Action, LinkGenerator hoặc Tag Helpers giúp tạo link từ metadata. CreatedAtAction trong WebLab tạo Location tới action đọc resource.

Bảng **Route WebLab api/students/{id:int}**: Request / Route/action / Kết quả. GET /api/students/5 — Match; action chạy — 200 nếu đã tạo, nếu không 404; GET /api/students/abc — Constraint không match — 404; GET /api/students/-1 — Match int; action chạy — 404 resource trong lab; POST /api/students/5 — Không có POST cho path này — 405, Allow phù hợp; GET /api/students?after=0&take=2 — Action List, query binding — 200; sort Id ổn định.

## [Đào sâu middle và các đánh đổi](https://client-ifz4.vercel.app/#/read/mvc-routing#middle)

Route {id:int} chấp nhận -1 về kiểu nhưng nghiệp vụ có thể từ chối hoặc không có resource. Constraint không thay validation; route không match khác record không tồn tại sau khi action chạy. GET có semantics safe, không dùng làm endpoint xóa. PathBase và proxy có thể thay đường dẫn công khai; phải cấu hình trusted forwarded headers, không ghép host từ input chưa tin.
