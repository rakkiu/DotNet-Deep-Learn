## Vị trí yêu cầu chung và nội dung giữ lại

- [Bản chất và vai trò](https://client-ifz4.vercel.app/#/read/csharp-generics#identity): Generic cho phép một type hoặc method nhận tham số kiểu, như List<T> hay Swap<T>. Khi dùng List<int>, int là một phần của hợp đồng được compiler kiểm tra. Generic không có nghĩa một collection trộn tùy ý mọi loại dữ liệu..
- [Nó giải quyết vấn đề gì?](https://client-ifz4.vercel.app/#/read/csharp-generics#problem): Collection dựa trên object buộc ép kiểu khi lấy ra; value type có thể bị boxing khi đưa vào. Viết một class riêng cho từng kiểu lại lặp logic. Generic giữ một cấu trúc thuật toán chung trong khi vẫn biết kiểu dữ liệu cụ thể ở từng cách sử dụng..
- [Tại sao nên dùng nó?](https://client-ifz4.vercel.app/#/read/csharp-generics#benefits): Lỗi thêm string vào List<int> được phát hiện khi build. Code dùng lại mà ít cast hơn, thường tránh boxing ở thao tác lưu giá trị T. Lợi ích hiệu năng phụ thuộc cách dùng: cast T sang object hay gọi API object vẫn có thể boxing..
- [Giới hạn và điều kiện áp dụng](https://client-ifz4.vercel.app/#/read/csharp-generics#limits): Không tham số hóa mọi thứ bằng nhiều T nếu code chỉ làm việc với một kiểu ổn định. Không dùng constraint quá rộng rồi ép kiểu trong thân hàm; nếu thuật toán cần khả năng so sánh, biểu đạt bằng constraint/interface phù hợp. Không hứa generic luôn không allocation..
- [Cơ chế hoạt động cốt lõi](https://client-ifz4.vercel.app/#/read/csharp-generics#mechanism): Compiler giữ thông tin tham số kiểu và kiểm tra ràng buộc where. Runtime tạo/điều phối code cho các kiểu generic đóng theo chiến lược của nó, có thể chia sẻ mã giữa một số reference type và chuyên biệt cho value type. Constraint cho phép gọi member được bảo đảm, không cần thử ép kiểu tùy ý lúc chạy..
- [Các khái niệm cốt lõi](https://client-ifz4.vercel.app/#/read/csharp-generics#concepts): Tham số kiểu T, Boxing, Constraint.
- [Tương tác với thành phần khác](https://client-ifz4.vercel.app/#/read/csharp-generics#integration): IEnumerable<T>, Task<T>, ILogger<T> và DbSet<TEntity> đều dùng generic để mang ý nghĩa kiểu qua nhiều tầng. Serializer và reflection có thể nhìn thấy generic arguments. Generic repository cần cân nhắc vì giao diện CRUD chung không luôn biểu đạt tốt query nghiệp vụ..
- [Ví dụ mở đầu và cách chạy](https://client-ifz4.vercel.app/#/read/csharp-generics#hello): tài liệu cụ thể ở cuối bài.
- [Cấu trúc thư mục & cấu hình](https://client-ifz4.vercel.app/#/read/csharp-generics#structure): Bố cục chính xác của từng ví dụ được liệt kê trong khối file của ví dụ đó. ## [Nền tảng junior cần giải thích được](https://client-ifz4.vercel.app/#/read/csharp-generics#junior)

Generic type/method nhận type parameter; inference suy luận từ argument nhưng không thay mọi constraint. default(T) phụ thuộc kiểu đóng. class/class? ràng buộc reference theo nullability, struct loại nullable value type, notnull yêu cầu kiểu không nullable theo phân tích; unmanaged yêu cầu kiểu không chứa managed reference. Base/interface constraints mở các member đó; new() cần constructor public không tham số và có quy tắc kết hợp, phải đặt sau các constraint thích hợp.

List<object> lưu int bằng boxing; List<int> thường không cần boxing khi lưu phần tử nhưng cast T sang object vẫn có thể boxing. object boxed=10 chỉ unbox trực tiếp thành int; (long)(int)boxed thực hiện unbox rồi numeric conversion. Nullable<int> không có giá trị boxing thành null; có giá trị boxing theo underlying int.

## [Đào sâu middle và các đánh đổi](https://client-ifz4.vercel.app/#/read/csharp-generics#middle)

List<T> invariant. IEnumerable<out T> cho reference covariance từ string tới object; Action<in T> nhận object dùng được nơi cần Action<string>. Không có conversion tương tự từ IEnumerable<int> sang IEnumerable<object> vì variance reference không thay boxing từng phần tử. Struct qua interface có thể boxing; constraint giúp một số constrained calls nhưng không hứa layout/JIT specialization cố định mọi runtime.
