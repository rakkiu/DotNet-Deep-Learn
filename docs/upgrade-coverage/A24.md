## Vị trí yêu cầu chung và nội dung giữ lại

- [Bản chất và vai trò](https://client-ifz4.vercel.app/#/read/aspnet-first-app#identity): ASP.NET Core là framework xây ứng dụng web và HTTP API trên .NET. Nó cung cấp hosting, middleware, routing, DI, cấu hình và logging; MVC là một mô hình xây giao diện/controller trong framework. Đây không phải ngôn ngữ và cũng không phải web server database..
- [Nó giải quyết vấn đề gì?](https://client-ifz4.vercel.app/#/read/aspnet-first-app#problem): Tự làm web từ socket buộc xử lý giao thức, request parsing, routing, bảo mật, logging và vòng đời connection. Các thế hệ ASP.NET cũ như Web Forms có mô hình riêng và thường gắn Windows. ASP.NET Core gom nền tảng web hiện đại, hỗ trợ nhiều host và mô hình lập trình..
- [Tại sao nên dùng nó?](https://client-ifz4.vercel.app/#/read/aspnet-first-app#benefits): Pipeline thống nhất, DI tích hợp và cấu hình theo môi trường giúp tổ chức ứng dụng dễ hơn việc tự ghép mọi thứ. Có thể triển khai trên Linux/container nếu dependency phù hợp. MVC không phải lựa chọn duy nhất: Minimal API và Razor Pages có thể đơn giản hơn cho nhu cầu tương ứng..
- [Giới hạn và điều kiện áp dụng](https://client-ifz4.vercel.app/#/read/aspnet-first-app#limits): Không chuyển app Web Forms cũ sang Core bằng cách chỉ đổi target framework. Không chọn MVC cho một API nhỏ chỉ vì thầy dùng MVC; cân nhắc độ phức tạp. Website tĩnh chỉ phục vụ nội dung không cần chạy server .NET riêng..
- [Cơ chế hoạt động cốt lõi](https://client-ifz4.vercel.app/#/read/aspnet-first-app#mechanism): Program.cs tạo builder, đăng ký services, build app và cấu hình pipeline. Kestrel nhận HTTP, tạo HttpContext rồi chuyển request qua middleware. Routing chọn endpoint; endpoint thực hiện logic và ghi response. Những phần trước/sau next cho phép middleware xử lý cả chiều vào lẫn chiều ra..
- [Các khái niệm cốt lõi](https://client-ifz4.vercel.app/#/read/aspnet-first-app#concepts): Request, Routing, Action result.
- [Tương tác với thành phần khác](https://client-ifz4.vercel.app/#/read/aspnet-first-app#integration): DI đưa DbContext, API client và service vào controller; configuration đọc appsettings, biến môi trường và nguồn khác theo thứ tự. Trình duyệt nhận HTML/JSON qua HTTP; database thường nằm sau server, không nối trực tiếp từ Razor/JS bằng connection string bí mật..
- [Ví dụ mở đầu và cách chạy](https://client-ifz4.vercel.app/#/read/aspnet-first-app#hello): tài liệu cụ thể ở cuối bài.
- [Cấu trúc thư mục & cấu hình](https://client-ifz4.vercel.app/#/read/aspnet-first-app#structure): Bố cục chính xác của từng ví dụ được liệt kê trong khối file của ví dụ đó. ## [Nền tảng junior cần giải thích được](https://client-ifz4.vercel.app/#/read/aspnet-first-app#junior)

WebApplicationBuilder thu cấu hình và ServiceCollection; builder.Services đăng ký cách tạo dependency trước Build. app cấu hình middleware/endpoint rồi Run mở server. Kestrel là server HTTP, không phải framework MVC hay database. MVC trả View, Web API thường trả data, Razor Pages tổ chức theo page, Minimal API hợp endpoint nhỏ gọn.

Routing tìm endpoint rồi MVC binding/validation chuẩn bị input cho action, action tạo result và result ghi response. Minimal hosting có thể bổ sung routing/auth middleware tự động khi điều kiện services/endpoint tương ứng được thỏa; WebLab dùng thứ tự tường minh để dễ theo dõi.

Sơ đồ **Vòng đời request trong WebLab**: Kestrel / host → Middleware A → B → static files → Routing → authentication → authorization → Binding / validation → action hoặc minimal endpoint → Action result → HTTP response; middleware unwind.

## [Đào sâu middle và các đánh đổi](https://client-ifz4.vercel.app/#/read/aspnet-first-app#middle)

HttpContext thuộc request, không giữ trong singleton hay tác vụ fire-and-forget vượt request. Inject scoped service khi xử lý, truyền RequestAborted qua I/O, log request/trace ID và đặt exception boundary phù hợp. Reverse proxy đứng trước Kestrel trong nhiều triển khai nhưng không phải mọi ứng dụng đều bắt buộc IIS/proxy. Configuration Development/Production ảnh hưởng diagnostics, không đồng nghĩa Debug/Release.
