## Vị trí yêu cầu chung và nội dung giữ lại

- [Bản chất và vai trò](https://client-ifz4.vercel.app/#/read/http-request-line#identity): HTTP định nghĩa cách client yêu cầu tài nguyên và server phản hồi. Bài của thầy xây server HTTP/1.1 tối giản trên TCP để nhìn thấy request line và luồng xử lý. Server học tập này khác Kestrel hoàn chỉnh và không đại diện parser HTTP/2 hay HTTP/3..
- [Nó giải quyết vấn đề gì?](https://client-ifz4.vercel.app/#/read/http-request-line#problem): Socket chỉ truyền byte; không tự biết byte nào là GET, đường dẫn tài nguyên hay trạng thái lỗi. HTTP đưa quy ước chung để browser và server của các bên khác nhau hiểu nhau. Tự viết phần nhỏ giúp hiểu framework đang làm việc gì bên dưới..
- [Tại sao nên dùng nó?](https://client-ifz4.vercel.app/#/read/http-request-line#benefits): Giao thức chuẩn có hệ sinh thái browser, proxy, công cụ và cache rộng. Kiến trúc tách accept loop, reader, router và writer dễ hiểu hơn một Worker xử lý tất cả. Trong ứng dụng thật, framework server đã được kiểm chứng giúp giảm công tự triển khai đầy đủ grammar và bảo vệ giao thức..
- [Giới hạn và điều kiện áp dụng](https://client-ifz4.vercel.app/#/read/http-request-line#limits): Không dùng parser Split đơn giản như server public. Không coi URL là đường dẫn file trực tiếp. Không chỉ hỗ trợ GET rồi trả 200 cho mọi method; hành vi và status phải phản ánh đúng khả năng và loại lỗi..
- [Cơ chế hoạt động cốt lõi](https://client-ifz4.vercel.app/#/read/http-request-line#mechanism): Trong HTTP/1.1, request line có method, request target và version, sau đó là headers, dòng trống và body theo framing. Server đọc dữ liệu có giới hạn, parse request thành model, chọn resource và tạo response. Byte có thể tới thành nhiều mảnh; timeout phải ngăn client giữ kết nối quá lâu chỉ để gửi dần header..
- [Các khái niệm cốt lõi](https://client-ifz4.vercel.app/#/read/http-request-line#concepts): Request line, Resource routing, Status code.
- [Tương tác với thành phần khác](https://client-ifz4.vercel.app/#/read/http-request-line#integration): Worker Service có host, DI, options và logging để quản lý accept loop/shutdown. WebServerOptions giữ địa chỉ/port; reader không nên tự quyết định nội dung business. Reverse proxy, TLS và giới hạn request là những phần còn thiếu của một demo TCP nhỏ..
- [Ví dụ mở đầu và cách chạy](https://client-ifz4.vercel.app/#/read/http-request-line#hello): tài liệu cụ thể ở cuối bài.
- [Cấu trúc thư mục & cấu hình](https://client-ifz4.vercel.app/#/read/http-request-line#structure): Bố cục chính xác của từng ví dụ được liệt kê trong khối file của ví dụ đó. Đặt mỗi mẫu trong thư mục trống riêng; xem Hướng dẫn chạy chung để tạo Console, hiểu bin/obj và debug. Project nhiều file hoặc lab có nút tải đầy đủ và lệnh chạy riêng..
- [Debug & log lỗi](https://client-ifz4.vercel.app/#/read/http-request-line#debug): Dùng curl -v xem request/response trên loopback. Log method, target, status, duration và request ID thay vì toàn bộ credential. Với lỗi parse, giữ fixture text an toàn để tái hiện riêng reader; lỗi bind/listen thuộc tầng socket, không phải lỗi routing..
- [Tài liệu & cộng đồng](https://client-ifz4.vercel.app/#/read/http-request-line#resources): tài liệu cụ thể ở cuối bài.

## [Nền tảng junior cần giải thích được](https://client-ifz4.vercel.app/#/read/http-request-line#junior)

Request line HTTP/1.1 có method, request target và version; target có thể chứa path/query theo dạng được chấp nhận. Safe nói không yêu cầu thay đổi state nghiệp vụ; idempotent nói tác động mong đợi khi lặp, không yêu cầu status/body/log giống hệt. DELETE có thể lần đầu 204, lần sau 404 mà vẫn idempotent về trạng thái.

400 cho input malformed; 404 resource vắng; 405 tài nguyên không cho method đã hiểu và có Allow phù hợp; method server không nhận biết/triển khai có thể 501. Fixture chỉ minh họa lựa chọn này trên chuỗi hoàn chỉnh, không là parser RFC hay server public.

## [Đào sâu middle và các đánh đổi](https://client-ifz4.vercel.app/#/read/http-request-line#middle)

Kiến trúc accept loop → reader → router → writer cần options validation, limits, timeout và shutdown có owner. Sơ đồ thư mục không chứng minh mọi thành phần đã có runtime. WebLab dùng Kestrel cho REST thật thay vì kéo dài Split thành parser production. HTTP/2 multiplexing và HTTP/3 có wire format khác, không dùng request-line parser này để đọc chúng.
