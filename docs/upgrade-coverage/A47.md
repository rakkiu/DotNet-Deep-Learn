## Vị trí yêu cầu chung và nội dung giữ lại

- [Bản chất và vai trò](https://client-ifz4.vercel.app/#/read/httpclient-json#identity): HttpClient gửi HTTP request và nhận response từ ứng dụng .NET. System.Text.Json chuyển giữa JSON và object .NET; GetFromJsonAsync kết hợp gửi request và deserialize. Chúng là thư viện, không phải API server hay database..
- [Nó giải quyết vấn đề gì?](https://client-ifz4.vercel.app/#/read/httpclient-json#problem): Tự gọi API bằng socket buộc xử lý DNS, connection, TLS, headers, framing và đọc body trước khi parse JSON. HttpClient cung cấp abstraction HTTP và handler quản lý transport. Serializer tránh tự cắt chuỗi JSON, nhưng vẫn cần xác định hợp đồng và kiểm tra dữ liệu..
- [Tại sao nên dùng nó?](https://client-ifz4.vercel.app/#/read/httpclient-json#benefits): API async, typed DTO và IHttpClientFactory giúp cấu hình nhất quán, tái dùng handler/connection và dễ test. So với client tạo/hủy cho từng request, chiến lược vòng đời phù hợp tránh cạn kết nối và xử lý thay đổi DNS tốt hơn. Không có nghĩa mọi API lỗi đều được tự retry an toàn..
- [Giới hạn và điều kiện áp dụng](https://client-ifz4.vercel.app/#/read/httpclient-json#limits): Không new/dispose client liên tục trong vòng lặp production; dùng long-lived client cấu hình lifetime kết nối hoặc factory. Không retry POST thanh toán tùy tiện vì có thể lặp tác dụng phụ. Không nhận URL tùy ý từ người dùng rồi server truy cập mà không kiểm soát đích đến..
- [Cơ chế hoạt động cốt lõi](https://client-ifz4.vercel.app/#/read/httpclient-json#mechanism): HttpClient chuyển request qua HttpMessageHandler; SocketsHttpHandler thường quản lý pool kết nối. BaseAddress kết hợp relative URI theo quy tắc URI, nên dấu / rất quan trọng. GetAsync trả response; EnsureSuccessStatusCode chấp nhận 2xx và ném với non-success. Deserialize có thể lỗi dù status thành công vì body không khớp JSON/contract..
- [Các khái niệm cốt lõi](https://client-ifz4.vercel.app/#/read/httpclient-json#concepts): HttpClient, BaseAddress, Deserialization.
- [Tương tác với thành phần khác](https://client-ifz4.vercel.app/#/read/httpclient-json#integration): Typed client được đăng ký qua AddHttpClient rồi inject vào service. Token/credential phải đi theo cơ chế phù hợp của API, không hardcode trong source. Truyền CancellationToken, giới hạn timeout/body, Dispose response và xác thực dữ liệu nghiệp vụ sau deserialize..
- [Ví dụ mở đầu và cách chạy](https://client-ifz4.vercel.app/#/read/httpclient-json#hello): tài liệu cụ thể ở cuối bài.
- [Cấu trúc thư mục & cấu hình](https://client-ifz4.vercel.app/#/read/httpclient-json#structure): Bố cục chính xác của từng ví dụ được liệt kê trong khối file của ví dụ đó. Đặt mỗi mẫu trong thư mục trống riêng; xem Hướng dẫn chạy chung để tạo Console, hiểu bin/obj và debug. Project nhiều file hoặc lab có nút tải đầy đủ và lệnh chạy riêng..
- [Debug & log lỗi](https://client-ifz4.vercel.app/#/read/httpclient-json#debug): Log method, URL đã lược dữ liệu nhạy cảm, status và duration; xem inner exception để phân biệt DNS/TLS/timeout/JSON. Với đường dẫn sai, in URI cuối sau ghép BaseAddress. Dùng HttpMessageHandler giả để kiểm tra behavior không phụ thuộc Internet, và DevTools/curl để đối chiếu API thực..

## [Nền tảng junior cần giải thích được](https://client-ifz4.vercel.app/#/read/httpclient-json#junior)

Hai chiến lược hợp lệ: HttpClient sống lâu với SocketsHttpHandler.PooledConnectionLifetime phù hợp, hoặc named/typed client từ IHttpClientFactory quản lý handler pool. Không giữ typed client transient trong singleton tùy tiện. BaseAddress + relative URI theo quy tắc URI, dấu / đầu hoặc cuối đổi path.

GetAsync trả response cần Dispose, EnsureSuccessStatusCode chấp nhận 2xx. GetFromJsonAsync có thể lỗi JSON dù status 2xx; 204 body rỗng, JSON null, property thiếu/sai schema phải được phân biệt. Web defaults có casing/options khác JsonSerializerOptions mặc định; deserialize không thay validation nghiệp vụ.

Bảng **Ghép URI**: BaseAddress / Relative / Kết quả. https://x.test/api/ — students — https://x.test/api/students; https://x.test/api — students — https://x.test/students; https://x.test/api/ — /students — https://x.test/students.

## [Đào sâu middle và các đánh đổi](https://client-ifz4.vercel.app/#/read/httpclient-json#middle)

ResponseHeadersRead cho phép bắt đầu xử lý trước body đầy đủ; timeout của lời gửi/headers không tự là budget trọn quá trình đọc body trong mọi API. Truyền token cả SendAsync và Read/Deserialize, đặt quota dữ liệu. Retry chỉ lỗi tạm thời theo idempotency, có budget/backoff/jitter; circuit breaker đổi hành vi tải, không tự sửa dependency. Shared mutable DefaultRequestHeaders và URL do caller tùy ý có rủi ro cạnh tranh/SSRF.
